# راهنمای MCP — اتصال جینکس هارنس به دنیای ابزارها

**MCP (Model Context Protocol)** استاندارد بازیه که ابزارها رو از «چیزی که باید براش کد بنویسی» به «چیزی که نصب می‌کنی» تبدیل کرده. هزاران سرور MCP آماده وجود داره — جست‌وجو، دیتابیس، گیتهاب، فایل‌سیستم، مرورگر، استرایپ و… — و همه یک زبان مشترک حرف می‌زنن.

جینکس هارنس از نسخه **۲.۰** یک کلاینت MCP کامل داخل خودش داره: هر ابزاری که یک سرور MCP ارائه بده، بدون حتی یک خط کد، تبدیل به ابزار واقعی ایجنتی می‌شه. و از نسخه **۲.۱** خودِ ایجنت هم می‌تونه سرور جدید وصل کنه — با کارت مجوز 🔐 و پشتیبانی کامل از سرورهای لاگین‌دار (OAuth).

---

## شروع سریع (۳۰ ثانیه)

یک خط به `portable/.env` اضافه کن و ری‌استارت کن:

```ini
JINX_MCP_SERVERS=fetch=https://mcp.example.com/mcp
```

همین. از این لحظه مدل ابزارهایی مثل `mcp_fetch_search` رو کنار ۶۰+ ابزار داخلی می‌بینه و می‌تونه صداشون کنه.

## راه دوم: به خود ایجنت بگو وصل کن (نسخهٔ ۲.۱)

اصلاً فایل دست نزن. توی تلگرام بنویس:

> «به این سرور MCP وصل شو: https://mcp.higgsfield.ai/mcp»

مراحل:

1. **کارت مجوز** — قبل از هر درخواستی به بیرون، کارت 🔐 «نیاز به اجازهٔ تو» با دکمه‌های *اجازه / رد / تا پایان این کار نپرس* میاد. مسیر فقط برای ادمین بازه و تا تصمیم نگیری بلاکه (پیش‌فرض ۸ دقیقه مهلت — `JINX_APPROVAL_TIMEOUT_MS`).
2. **تشخیص خودکار نوع سرور:**
   - بدون احراز هویت → اتصال فوری + ثبت ابزارها
   - کلید API → ایجنت ازت کلید رو می‌پرسه (بعد `Authorization: Bearer` و در صورت رد، `X-Api-Key` امتحان می‌شه)
   - OAuth (لاگین با اکانت، مثل Higgsfield/Runway/HeyGen) → لینک لاگین برات میاد؛ بعد از لاگین و تأیید، توکن ذخیره و از اون به بعد خودکار refresh می‌شه
3. **ماندگاری** — سرورهای وصل‌شده در `portable/data/mcp-dynamic.json` ذخیره می‌شن و بعد از ری‌استارت هم اشن. حذف: «سرور فلان رو قطع کن» (`mcp_disconnect`).

### تنظیم OAuth (لاگین‌دارها)

برای اینکه صفحهٔ بازگشت لاگین روی خود ایجنیت باز شه، آدرس عمومی CGI رو معرفی کن:

```ini
# portable/.env
JINX_PUBLIC_URL=https://your-host.example/cgi-bin/index.cgi
```

- کال‌بک روی `/oauth/mcp/callback` سرو می‌شه (از طریق همون `index.cgi` — بدون پورت باز).
- اگر مرورگر به کال‌بک نرسید (مثلاً سرور لاگین فقط localhost رو قبول می‌کنه): **آدرس نهایی** رو از نوار آدرس مرورگر کپی کن و همون‌جا توی چت بفرست — ایجنت با `mcp_oauth_complete` ادامه‌ی تبادل رو خودش کامل می‌کنه.
- وضعیت جریان‌های در جریان و توکن‌ها: `https://your-host/…/oauth/mcp/status` (بدون نمایش خود توکن‌ها).
- توکن‌ها در `portable/data/mcp-tokens.json` با مجوز `600` ذخیره می‌شن و هرگز لاگ نمی‌شن.

## تنظیم چند سرور

با کاما جدا کن؛ اسم هر سرور اختیاریه ولی خواناتره:

```ini
JINX_MCP_SERVERS=fetch=https://mcp.example.com/mcp, time=https://time.example.com/mcp, https://another.example.com/mcp
```

- `name=url` → اسم دلخواه (اسم ابزارها می‌شه `mcp_<name>_<tool>`)
- فقط `url` → اسم به‌صورت خودکار از hostname برداشته می‌شه

### احراز هویت (Auth)

اگه سرورت توکن می‌خواد، برای هر سرور یک متغیر جدا تعریف کن — مقدارش می‌شه مقدار کامل هدر `Authorization`:

```ini
JINX_MCP_SERVERS=github=https://mcp.github.example/mcp
JINX_MCP_AUTH_GITHUB=Bearer ghp_yourtoken
```

> کلیدها هرگز لاگ نمی‌شن و هرگز برای سرور دیگه‌ای فرستاده نمی‌شن.

## حالت پیشرفته: mcp.json

برای کنترل بیشتر (هدرهای سفارشی، timeout جدا، خاموش/روشن کردن موقت)، فایل `portable/mcp.json.example` رو به `portable/mcp.json` کپی کن و ویرایش کن:

```json
{
  "servers": [
    {
      "name": "mydb",
      "url": "https://mcp.mydb.example/mcp",
      "auth": "Bearer …",
      "headers": { "X-Api-Key": "…" },
      "enabled": true,
      "timeoutMs": 30000
    }
  ]
}
```

اگه `mcp.json` سروری داشته باشه، اولویت باهاشه.

## ابزارهای متا

مدل خودش هم دو ابزار مدیریت داره:

| ابزار | کار |
|---|---|
| `mcp_servers` | لیست سرورها + وضعیت + تعداد ابزار هر کدوم (با `refresh: true` اول اسکن می‌کنه) |
| `mcp_refresh` | اسکن مجدد همه سرورها — وقتی کانفیگ رو عوض کردی، لازم نیست ری‌استارت کنی |
| `mcp_connect` | وصل‌کردن سرور جدید (فقط ادمین + کارت مجوز) — بدون auth / کلید API / OAuth |
| `mcp_disconnect` | قطع‌کردن سروری که خود ایجنت وصل کرده |
| `mcp_oauth_complete` | تکمیل لاگین OAuth از روی آدرسی که کاربر کپی کرده |

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `JINX_MCP_SERVERS` | — | لیست سرورها (بالا رو ببین) |
| `JINX_MCP_TIMEOUT_MS` | `30000` | سقف زمان هر درخواست JSON-RPC |
| `JINX_MCP_MAX_TOOLS` | `300` | حداکثر تعداد ابزار MCP ثبت‌شده |
| `JINX_MCP_OFF` | — | `1` = غیرفعال‌کردن کامل پل MCP |
| `JINX_MCP_ALLOW_CONNECT` | `1` | `0` = ممنوع‌کردن اتصال خودکار توسط ایجنت |
| `JINX_PUBLIC_URL` | — | آدرس عمومی CGI — برای لاگین‌های OAuth لازمه |
| `JINX_MCP_TOKENS` | — | مسیر جایگزین فایل توکن‌های OAuth (برای تست) |
| `JINX_MCP_JSON` | — | مسیر جایگزین فایل کانفیگ (برای تست) |
| `JINX_MCP_REGISTRY` | — | مسیر جایگزین کش رجیستری |

## بعد از ری‌استارت چی می‌شه؟

ابزارها از **کش** (`portable/data/mcp-registry.json`) فوراً ثبت می‌شن — بدون حتی یک درخواست شبکه. بعد در پس‌زمینه اسکن تازه انجام می‌شه و اگه سروری ابزار جدید اضافه کرده باشه، خودکار ثبت می‌شه. فقط در **اولین بوتِ همیشگی** (بدون کش) حدود ۵۰ میلی‌ثانیه طول می‌کشه تا ابزارها برسن — بعدش همیشه فوریه.

## عیب‌یابی

| نشانه | علت رایج | راه‌حل |
|---|---|---|
| `authentication rejected (HTTP 401)` | توکن اشتباه یا جاافتاده | `JINX_MCP_AUTH_<NAME>` رو چک کن |
| `server does not expose Streamable HTTP at this URL (404)` | آدرس اشتباه یا سرور فقط stdio است | آدرس endpoint رو چک کن؛ سرورهای stdi از راه دور قابل اتصال نیستن |
| `fetch failed` | دامنه قطعه/DNS/فایروال | `curl` کن از همون هاست |
| ابزار جدید بعد از تغییر کانفیگ نمیاد | کانفیگ موقع بوت خونده می‌شه | به ایجنت بگو «mcp refresh کن» یا ری‌استارت کن |
| سروری error می‌ده ولی بقیه کار می‌کنن | همون سرور مشکل داره | بقیه دست‌نخورده می‌مونن — طراحی به این صورته |

تست سلامت کامل با MCP: `node app.js --check` — هر سرور رو initialize و tools/list می‌کنه و تعداد ابزارش رو گزارش می‌ده.

## امنیت

- سرورهای کانفیگی رو **فقط صاحب اکانت** از فایل روی دیسک تنظیم می‌کنه. سرورهایی که خود ایجنت وصل می‌کنه، اول از **کارت مجوز انسانی** (بلاک تا زمان تصمیم، فقط ادمین) رد می‌شن — و با `JINX_MCP_ALLOW_CONNECT=0` این مسیر کلاً بسته می‌شه.
- توکن‌های OAuth و کلیدهای API در فایل‌های `600` ذخیره می‌شن، هرگز لاگ نمی‌شن و فقط به سرور خودشان فرستاده می‌شن.
- خروجی هر ابزار قبل از رسیدن به مدل به **۴۸ کیلوبایت** محدود می‌شه.
- کاربران غیر ادمین از همان بودجه ابزار و دروازه تأیید ابزارهای داخلی رد می‌شن.
- جزئیات کامل: [SECURITY.md](../SECURITY.md)

## تست

کل پل MCP با ۳۸ + ۴۳ تست واحد (از جمله جریان کامل OAuth با سرور احراز هویت ماک) + یک تست انتها-به-انتهای واقعی (پیام تلگرام → مدل → ابزار MCP → جواب → اتصال سرور جدید با مجوز → لاگین OAuth → ابزار لاگین‌دار) پوشش داده شده:

```bash
node test/run-all.cjs
```
